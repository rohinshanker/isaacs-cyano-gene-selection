## Safe credential handling

- **Treat the repository as public**: the site is deployed at rohinshanker.github.io and serves its downloads from GitHub raw URLs (`docs/validation/source-ledger.md:9-12`). No password, token, cookie, API key or account name tied to a credential is ever written into the repository, a ticket, a SEND/RET file, a TSV, a commit message, or session memory. The same applies to supplied PDFs: they stay outside the working tree.
- **Prefer no credential transfer at all.** The owner logs in in his own browser and exports what is needed; the agent reads only the exported file.
- **If a session must authenticate**, the owner stores the secret through the Claude Science credential store (Customize → Credentials), which exposes it only as an environment variable to the specific cell that declares it and removes it afterwards; it is never typed into chat, pasted into a request text, or printed. Use a dedicated account where the service's terms allow one, scope it to read access, and rotate or revoke it when the task ends.
- **Mechanism caveat.** This session has HTTP-client access, not an interactive logged-in browser; whether a given service's authenticated pages can be read that way is untested. Driving the Claude Science application itself through browser automation is forbidden by the contract (`docs/validation/claude-science-handoff.md:267-271`).
- **No circumvention.** CAPTCHAs, proof-of-work challenges, metering, 403s and paywalls are left alone; the remedy is always a human with legitimate access (`docs/validation/claude-science-handoff.md:17-20, 41-43, 64-65`).
- **Yale Bouchet** (OWN-08): the folding ticket already requires account secrets to stay out of the browser and out of documents (`docs/notes/tickets/O_folding-compute-backend__20260930.md:79, :157`).
