# BioCyc ortholog-annotation contract

- Purpose: Fix the source precedence, disagreement disclosure, evidence labels, scope limits and probe rules for BioCyc-derived annotation of UTEX 2973.
- Scope: BioCyc v30.0 UTEX 2973 and PCC 7942 (`SYNEL`) databases, EcoCyc via KEGG orthology, and the ortholog table; no data is admitted by this document.
- Last verified: 2026-10-14

## Source priority (owner decision, 2026-10-14)

1. UTEX 2973 BioCyc predictions and PCC 7942 (`SYNEL`) annotations are both
   included, and UTEX takes precedence over PCC 7942.
2. *E. coli* (EcoCyc) fills only gaps that neither UTEX nor PCC 7942 covers, at
   lower priority. A gap is a locus and data type with no value from either
   source; an *E. coli* value never replaces or hides one.
3. Priority orders display and fill. It is not evidence of greater accuracy.
   Where a lower-priority source disagrees with a higher one for the same locus
   and data type, keep both values, each under its own source, and disclose the
   disagreement; never silently drop or override either.

## Evidence labels

Follow [data-contract.md](data-contract.md#evidence-coverage-and-cross-organism-transfer).

- UTEX 2973 BioCyc content is Tier 3 (uncurated), generated by PathoLogic in
  2020 from an older annotation of the pinned assembly `GCF_000817325.1`. Its
  pathway, reaction and transcription-unit content is computational prediction,
  displayed as predicted and never as measurement. Its gene and product text
  re-presents the pinned RefSeq annotation and adds nothing.
- PCC 7942 content is `transferred` with `sisterStrain: true` and the strain
  named wherever shown. PCC 7942 coordinates never go on the UTEX axis.
- *E. coli* content is `transferred` at evidence rank 4. It supports a conserved
  bacterial function; it does not establish cyanobacteria-specific regulation,
  condition-specific expression or UTEX 2973 essentiality.

## Probing BioCyc

`organism-summary?orgid=` answers an unknown orgid with HTTP 200 and a full
*E. coli* K-12 MG1655 page, so status is never evidence of a database.

- Run an invalid-orgid control (`GCF_999999999`) and compare the organism named
  on each returned page with the strain requested.
- Confirm a miss by the second route, `biocyc-pgdb-list.shtml`, which links
  entries as `?object=<ORGID>` (PCC 7942 is `SYNEL`, not its assembly accession).
- Check for the `account-required.shtml` redirect. No agent creates an account.
  Since 2026-10-16 the owner keeps their own BioCyc login in the macOS keychain
  item `biocyc-login`, and agents use it only through BioCyc web services
  (`websvc.biocyc.org/credentials/login/`), never printing or saving the
  password; the session cookie stays in scratch space.
- Record BioCyc version, tier, retrieval date and a checksum of any saved page.

## Ortholog product-text reader

`tools/ortholog_annotations.py` reads the frozen returned table and corrects
only encoded commas (`%2C`, case-insensitive) in `product`. It decodes once:
literal `+`, `%252C` and other percent escapes remain literal, and every other
cell and row order are preserved. Original product text remains accessible for
provenance. The table remains evidence, not an admitted BioCyc layer or join.

The reader checks the source SHA-256 above before parsing. The source schema,
unique locus tags and complete records must pass before any output is written.
Export a derivative to a fresh path:

```sh
python tools/ortholog_annotations.py --out /tmp/cyano-ortholog-products.tsv
```

An optional `--source PATH` accepts only a byte-identical copy of the frozen
source. `read_table()` returns rows with `raw_product`, decoded `product`, and
all original `cells`; `decoded_cells()` returns the export fields. Exports retain
the original TSV columns and refuse existing output paths. Never replace the source or relax its pin
to accept a different return.

Validation checks the real 2,715 rows: exactly 46 product cells change, every
other cell remains equal, and the original bytes retain their digest. As an
independent existing-data check, all 2,715 decoded products match the admitted
native `site/data/genes.json` products by exact locus ID. That comparison checks
text only; it does not admit the returned orthology or annotation evidence.

Run the focused contract with `python -m pytest -q tests/test_ortholog_annotations.py`.
The pinned export is 318,164 bytes, SHA-256
`4cfd9dcfd397bb52e55c3722bbab94005d742336d21e0242d700040d4e8c0b4e`.
