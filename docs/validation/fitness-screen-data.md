# Condition-resolved fitness screens

Fitness is a separate measured data type, `fitness` with platform `RB-TnSeq`,
shown in the Fitness screen selection tab and the Fitness metric family.
Values are signed gene-fitness scores on the authors' log2 scale relative to
Time 0. Preserve negative values and use a diverging ramp. Barcode counts,
expression abundance and one-condition essentiality calls are different
quantities and must not be relabelled or pooled as fitness.
Gene fitness is the authors' weighted, normalized insertion-strain score; it
must not be described as a raw barcode-count ratio. In the biofilm assay a
positive score means enrichment of insertion mutants in the fraction, not a
prediction that increasing the intact gene improves UTEX growth.

## Pinned sources and joins

| Source | Published quantity and layer boundary | UTEX 2973 coverage per layer |

| [GSE205443 / Simkovsky 2022](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE205443) | Nine published fitness columns from Supplementary File S4, `Data_Sheet_4.XLSX`, sheet `2) Gene Fitness and T-values`, one per biofilm-assay fraction. GSE205445 is the SuperSeries and supplies no additional fitness table. | 1,835 genes with values; 85 source identifiers unmapped |
| [Fitness Browser, SynE / Price 2018](https://fit.genomics.lbl.gov/cgi-bin/org.cgi?orgId=SynE) | All 129 experiments in the pinned 1,899-gene table, grouped into 90 condition sets by the experiment table's compound, concentration and units. A repeated condition set is the arithmetic mean of its named experiments. | 1,819 genes with values; 80 source identifiers unmapped |

Both sources were measured in PCC 7942. Transfer only through one-to-one
`pcc7942_old_locus_tag` rows of the pinned identifier crosswalk. Do not guess an
unmatched locus, treat an absent value as zero, or transfer sister-strain
coordinates onto the UTEX genome. Retain the cross-strain caveat and source
citation wherever values are shown or exported.
The fitness table is keyed entirely by gene identifier; do not restrict it to
digits-only locus suffixes. Valid `Synpcc7942_1912a` and `Synpcc7942_B...`
identifiers use the same approved exact crosswalk as numeric identifiers.

The ingest specifications are
[`GSE205443.json`](../../data/expression/ingest/GSE205443.json) and
[`FITNESS_BROWSER_SynE.json`](../../data/expression/ingest/FITNESS_BROWSER_SynE.json).
The latter is generated by `tools/build_fitness_browser_spec.py`, which pins
both the fitness table and experiment table. The original bytes are staged in
gitignored `data/interim/expression/`; an access challenge requires the owner's
saved download. A later download is a different input until its checksums and
experiment coverage are deliberately reviewed. Follow the
[source ledger](source-ledger.md#fitness-screen-sources) for attribution.

T-values and cofitness are not shipped or used as a significance filter. The
fitness values remain the published values. Repeated experiments are not
labelled biological replicates when the experiment table does not say that.
The Fitness Browser table supplies temperature, medium and culture format but
no irradiance, light regime, CO2 or growth phase; these remain explicitly
unknown and do not prevent displaying the measured score.
For the biofilm assays, fluorescence does not establish a continuous-light
schedule. Retain reported preparation stages and vessel identities separately
from sampling-stage claims. Read methods, figures and captions together when
assigning replication: one published score column is not a biological replicate
count, and pooled cultures provide no separately shipped replicate values.

## Pooling and selection

Under the owner's 2026-10-07 decision, the Fitness Browser's 90 condition sets
are selected by default and form one pooled row. The type metric is the
arithmetic mean of available condition-set fitness values on the shared log2
scale; it gives each selected condition set equal weight, rather than weighting
by the number of experiments in it. Missing values remain unknown. The nine
GSE205443 biofilm fractions stay outside this default pool.

Choose conditions opens a compound-by-dose checkbox grid. Every condition set
appears exactly once, with the undosed BG-11 control apart. A compound checkbox
selects its tested doses; readers can instead select individual doses, all
conditions or none in the draft. Done applies the draft, Escape discards it,
and the exact committed selection travels in the `ds` link field. The exported
provenance records each contributor.

A grid opened over the selection dialog is the topmost modal: the lower dialog
is inert, focus stays in the grid, and Escape closes only the grid and returns
focus to its opener. Closing the outer dialog returns focus to the toolbar.
Long source identifiers must wrap within provenance notes at narrow widths.
The calculation disclosure describes the actual number of selected condition
sets; it must not reuse a single contributor's sample-column count. Preserve
source-specific limitations, including missing T-values, under pooling, and
link the fitness archive rather than the study's RNA-seq arm. Fitness is
explicitly excluded from traffic/activity thresholds, regardless of its label,
key or descriptive unit text.

## Reproduction and acceptance

With the pinned originals staged, use an isolated checkout and run:

```sh
.venv/bin/python tools/build_fitness_browser_spec.py --check
.venv/bin/python tools/ingest_expression.py data/expression/ingest/GSE205443.json
.venv/bin/python tools/ingest_expression.py data/expression/ingest/FITNESS_BROWSER_SynE.json
.venv/bin/python scripts/build_features.py
.venv/bin/python tools/build_data_manifest.py build
node --test tests/js/fitness-compendium.test.mjs tests/js/data-sources-compendium.test.mjs
npm test
.venv/bin/python -m pytest -q
.venv/bin/python tools/validate_contract.py
```

Verify every one of the 129 input experiment columns occurs exactly once in
the 90 condition sets, every derived TSV matches its checksum, values and
missingness match the shipped sidecar, and source/target coverage matches the
table above. The release has 99 fitness layers in total. Reproduce repeated-set
means from the pinned input, including signed values, without adding a new
normalization or replacing the authors' fitness calculation.

Render the actual site from that checkout on a task-specific port. Open it with
`?uiArtifacts=<absolute ignored artifact directory>` and run:

```sh
playwright-cli -s=<unique-session> run-code --filename=tools/ui/check_fitness_controls.js
```

The browser check covers the pooled default, separate biofilm fractions,
compound and dose subsets, exact link restoration, empty draft, modal dismissal,
keyboard focus and diagnostics. It checks phone, tablet, desktop and wide
viewports, plus both sides of the grid's 700-pixel breakpoint. Inspect the
screenshots as well as the assertions; the long pooled source note and all 90
grid cells must stay usable without page overflow. Also apply the repository's
[release gate](release-gate.md) before publication.
